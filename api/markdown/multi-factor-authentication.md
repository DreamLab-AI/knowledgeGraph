- ### Definition
  - [[Multi-Factor Authentication]] is a security mechanism requiring claimants to present two or more independent verification factors from distinct categories — knowledge, possession, and inherence — building on a base [[Authentication Mechanism]] to ensure that compromise of one credential alone cannot grant unauthorised access.
- ### Relationships
  - Multi-factor authentication is a specific, stronger form of [[Authentication Mechanism]] and is directly governed by [[Authentication Standards]] and [[Cybersecurity Standard]] requirements. It enables robust [[Access Control]] and supports [[Digital Identity Management]] by raising the assurance level of identity proofs. Practically it uses [[Biometric Binding Mechanism]] components and [[Cryptographic Keys]] (in hardware tokens and asymmetric challenge-response schemes) to deliver independent factors, ultimately contributing to [[Data Security]].
- ### Content
  - The security principle underlying multi-factor authentication is that independent factors drawn from different categories are uncorrelated in their vulnerability: an attacker who steals a password does not automatically obtain the user's registered mobile device, and one who clones a SIM card does not thereby learn the user's memorised passphrase. This independence transforms credential compromise from a sufficient condition for access into merely a necessary one among several, dramatically raising the cost and complexity of successful attacks.

  - Common MFA implementations include time-based one-time passwords (TOTP) generated by authenticator applications and verified against a shared secret stored on the server, push notifications to a registered mobile device that the user must approve, and hardware security keys implementing the FIDO2/WebAuthn standard via USB or NFC. Hardware security keys represent the highest assurance approach for software-based MFA because they are phishing-resistant — the cryptographic binding between key and origin prevents use on fraudulent sites that merely resemble the target.

  - Regulatory and compliance mandates have made MFA effectively obligatory for many categories of system. Payment services regulations, healthcare data protection rules, and national cybersecurity frameworks increasingly specify MFA as a minimum control for access to privileged functions or sensitive personal data. The [[Authentication Standards]] landscape — encompassing NIST SP 800-63, ISO/IEC 27001 controls, and sector-specific guidance — provides the normative basis on which these mandates rest.

  - Balancing security with usability is the central design challenge for MFA deployments. Excessive friction causes users to seek workarounds, defeating the security benefit. Risk-based or step-up authentication approaches mitigate this by invoking full MFA only when risk signals — unfamiliar device, anomalous location, high-value transaction — exceed a threshold, allowing low-risk routine access with lighter friction whilst preserving strong assurance where it matters most. This adaptive model is now standard in enterprise [[Access Control System]] platforms.
