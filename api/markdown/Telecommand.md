
A telecommand is an instruction sent over a communications link to request an action by a spacecraft or one of its subsystems.

A ground system prepares commands for mission operations and transmits them on an uplink. Onboard command and data handling receives and decodes the command data, then routes platform instructions to the relevant subsystem or passes payload instructions to the payload. Commands may change spacecraft configuration, control platform functions or direct payload activity.[^1][^2][^3]

Commands can be scheduled in sequences for execution between ground contacts, and spacecraft may act autonomously when no immediate contact is available. Sending a command, receiving it, accepting it and carrying out its intended action are separate events. Telemetry and other mission reports are used to check the spacecraft’s response.[^2][^3][^4]

CCSDS 232.0-B-4, the current opened TC Space Data Link Protocol issue, specifies protocol services and procedures for an asynchronous transfer frame. It standardises a data-link layer; it does not define each mission command’s meaning, operational review process or authority to command. CCSDS Blue Books are recommended standards adopted through agency standards programmes and cross-support arrangements, not automatic implementations in every spacecraft.[^5][^6][^7]

Telecommand is related to telemetry through the command-and-response loop, but the terms refer to different directions and functions. The presence of a telecommand link alone does not establish command execution or the mission’s control authority.[^1][^2][^6]
