- ### Definition
  - [[Real-Time Computation]] is a computational paradigm in which result correctness depends on both logical accuracy and timely delivery within externally imposed deadlines, requiring deterministic execution, bounded [[Latency]], and schedulers that prioritise deadline-critical tasks—foundational to [[Control System|control systems]], robotics, and interactive [[Autonomous System|autonomous systems]].

- ### Relationships
  - Real-time computation underpins [[Control System]] operation by guaranteeing that sensor measurements are processed and actuation commands issued within physically meaningful time windows. It is tightly coupled to [[Sensor Fusion]] pipelines that merge heterogeneous [[Sensor Input|sensor inputs]] under time constraints. [[Edge Computing]] architectures are favoured for real-time deployments because they minimise network [[Latency]]. [[Parallel Processing]] is a key enabling technique that distributes computation to meet deadlines across multiple cores. [[Real-Time AI]] inference extends the paradigm to neural network forward passes in safety-critical autonomous systems.

- ### Content
  - Real-time computing emerged as a formal discipline alongside the development of process control computers in the 1960s, where factory and aerospace applications required computers to close control loops within milliseconds. Early real-time operating systems (RTOS) such as VRTX and later QNX provided deterministic scheduling—primarily rate-monotonic and earliest-deadline-first algorithms proven optimal for preemptive fixed-priority scheduling. The distinction between hard and soft real-time emerged from the observation that different application domains tolerated timing failures differently: a missed deadline in a nuclear reactor control loop is categorically different from a dropped audio frame in a media player.

  - The architectural requirements of real-time computation differ substantially from general-purpose systems. Memory must be pre-allocated to avoid non-deterministic garbage collection pauses; interrupt handlers must execute in bounded time; cache behaviour must be predictable; and operating system scheduling must be analysable under worst-case assumptions. Static timing analysis tools compute Worst-Case Execution Time (WCET) bounds by modelling processor pipelines and caches, enabling system designers to prove—mathematically or empirically—that deadlines will be met. Multicore real-time systems introduce additional complexity through cache coherence effects and shared bus contention that can violate single-core timing bounds.

  - The significance of real-time computation extends across any application where physical processes evolve faster than human reaction and demand automated closed-loop control: engine management in automobiles, flight control in aircraft, servo control in industrial robots, and frequency regulation in power grids. Financial high-frequency trading systems operate at nanosecond latency, making hardware co-location and kernel-bypass networking as important as algorithmic efficiency. In interactive media, real-time rendering systems such as game engines treat frame-time budgets as soft deadlines, trading visual fidelity for frame-rate consistency under varying scene complexity.

  - By 2024 and 2025, real-time computation requirements intensified as autonomous vehicle stacks, surgical robots, and drone swarms demanded AI inference at millisecond latency. This drove the development of dedicated neural processing units (NPUs) with deterministic execution models and the adaptation of RTOS concepts for AI accelerator scheduling. The AUTOSAR Adaptive Platform and ROS 2 incorporated real-time executor patterns for automotive and robotic AI pipelines. Concurrently, research into model pruning, quantisation, and early-exit architectures sought to reduce worst-case neural network inference time to meet hard real-time bounds that classical deep learning deployments could not reliably satisfy.
